## 3. Embedding dimension choice (768) — justification

The Gemini API uses a Matryoshka representation: the same model accepts
truncating the output via `outputDimensionality` without needing another model.
**768** was chosen instead of the default (3072) because:

- The storage cost and the `VECTOR_COSINE` computation cost in IRIS are
  proportional to the dimension — 768 is 4x lighter than 3072 for a small
  demonstration corpus, with no need for production-grade precision at large
  scale.
- 768 is a widely used/tested dimension in general-purpose embeddings
  (comparable to models such as `text-embedding-ada-002`), reducing the risk of
  atypical behavior.

Record in the contest article as the answer to the "Chunking/embedding
justification" criterion (+2).

## 3.2 Data schema, chunking, ingestion and query (09/09/2026)

- **Schema**: `Guardian_RAG.Document` (Source, Title, Version, CollectedAt) and
  `Guardian_RAG.Chunk` (DocumentId, ChunkIndex, ChunkText,
  `Embedding VECTOR(DOUBLE, 768)`, EmbeddingModel, CreatedAt) — created via
  direct DDL (`Guardian.RAG.Schema`), the same approach validated in
  VR-001/002, not via a persistent-class `Property` (avoids unverified
  ObjectScript vector-type syntax).
- **Chunking** (`Guardian.RAG.Ingestion`): grouping by paragraph (separator
  `\n\n`) up to 800 characters, with paragraphs larger than that split into
  sliding windows with 150 characters of overlap. Justification: paragraphs
  preserve units of meaning; 800 characters balances enough context per
  fragment with retrieval precision for this project's documents (technical
  Markdown, short to medium paragraphs); overlap reduces information loss on
  cuts in the middle of an explanation.
- **Initial corpus**: the project's own phase documents (`00_MASTER_PLAN.md` to
  `04_PHASE_3_RAG_ASSISTANT.md`) — own content, already authorized, and directly
  relevant to the domain ("how IRIS Production Guardian works"). 79 fragments
  generated from 5 documents.
- **Query** (`Guardian.RAG.Query`): question embedding, `TOP 5` by
  `VECTOR_COSINE`, a prompt instructing the model to answer only with the
  provided context and cite the source. Abstention if the best similarity is
  below `MinSimilarity`.
- **Calibration of the abstention threshold**: started at 0.5, adjusted to
  **0.58** after two real observed points — relevant question ("why doesn't
  IntegratedML work") = 0.653; irrelevant question ("chocolate cake recipe") =
  0.518 (would pass the filter at 0.5). Still a heuristic with few points, not
  statistically validated — better calibration is left as future work with a
  larger evaluation set.
- **Page**: `Guardian.UI.RAGPage` (`/csp/guardian/Guardian.UI.RAGPage.cls`) — a
  simple form (GET, no JS), all logic in COS.

### Real errors found and fixed

1. `%SQL.Statement` has no `%GetLastIdentity()` method (it does not exist in the
   real API). `LAST_IDENTITY()` via SQL also does not work when called in a
   **separate** `%SQL.Statement` from the INSERT (tested and confirmed empty).
   Fixed by using the `%ROWID` of the INSERT's own resultset, which works
   reliably.
2. `$Select($IsObject($Get(tResp.error)):...)` — `$Get` does not apply to a
   `%DynamicObject` property (error `Class '%Library.DynamicObject' does not
   support MultiDimensional operations`). Fixed by using `tResp.%Get("error")`,
   the correct way to access a key that may not exist in a dynamic object.
3. **Encoding false alarm, recorded so the investigation is not repeated**:
   debugging the API via `iris session` (a Docker terminal without a real TTY)
   shows corrupted accents as spaces or `�`/`Ã§`. A hexdump of the real HTTP
   response (via `curl`, raw bytes) confirmed perfectly valid UTF-8 end to end —
   the problem was only the debugging terminal's display, not the application.
   **Do not presume an encoding bug from terminal output — always check the real
   bytes (hexdump) or the `$Length`/character codes before changing code because
   of it.**
4. **Resilience to model unavailability**: the Gemini API returned a real `503
   UNAVAILABLE` during the tests ("high demand"). Without handling, this took
   the page down with the generic CSP error. A `Try/Catch` was added in
   `Guardian.UI.RAGPage` to show a clear message instead of hanging —
   consistent with the MVP requirement that model unavailability must not
   prevent use of the application.

## 6. Hybrid search (lexical + vector) — 10/09/2026

+3 bonus implemented: `Guardian.RAG.Query.Ask` now fuses two independent
rankings before assembling the final TopK.

- **Lexical index**: `idxChunkTextFind`, an `%iFind.Index.Basic` index (IRIS's
  native full-text search) on `Guardian_RAG.Chunk.ChunkText`, created in
  `Guardian.RAG.Schema.Setup` — verified live that it works in the Community
  Edition without an extra license (the same family of finding as
  VR-001/VR-002). Search via the SQL predicate `%FIND search_index(...)`.
- **Fusion**: Reciprocal Rank Fusion (RRF, `score = 1/(k+rank)`, `k=60`, the
  reference value from the IR literature, with no tuning specific to this small
  corpus). Pool of up to 15 candidates from each search (vector and lexical),
  final TopK remains 5.
- **Limitation found and decision recorded**: iFind's native ranking function
  (`%iFind.Rank`) did not accept the expected syntax in live tests (`Field
  'IDXCHUNKTEXTFIND' not found`) — instead of guessing the correct syntax or
  faking a rank position that was not calculated, a lexical match adds a fixed
  bonus (equivalent to rank 1) in the fusion. It is an honest simplification,
  not a fine-grained lexical relevance metric — recorded here so it is not
  confused with a real `%iFind.Rank` if someone tries to optimize this later.
- **Abstention was not changed**: the `MinSimilarity` gate (section 5) is still
  based *only* on the best pure vector similarity, never on the RRF score — a
  deliberate decision so as not to invalidate the calibration already tested
  with the 2 real points (0.653 relevant / 0.518 irrelevant).
- **Real tests (10/09/2026)**:
  - "What does error #5005 mean in the failure scenario?" → retrieved and
    correctly cited the chunk with `ERROR #5005`, 5 sources, no abstention (best
    similarity 0.677).
  - "chocolate cake recipe" (irrelevant) → abstention kept (best similarity
    0.521, below the threshold) — confirms that the hybrid fusion did not break
    the already-validated abstention calibration.
  - "Explain GeminiClient" → retrieved 5 sources from Phase 3, all above the
    threshold. In that specific test Gemini also returned a real timeout error
    (`ERROR #5922`) on a first attempt — this reinforces the already-recorded
    pending item about free-tier instability/exhaustion (see `00_MASTER_PLAN.md`
    §8); on the second attempt it worked normally.

### 7.1 Calibration of the abstention threshold

`RunCalibration()` runs the 10 questions against the **production** corpus
(`Guardian_RAG.Chunk`, the same one used by the real RAG Assistant) via
`Guardian.RAG.Query.Retrieve`. Real result:

| Question | Relevant? | Best similarity |
|---|---|---|
| Why was Gemini chosen? | yes | 0.761 |
| Embedding dimension? | yes | 0.738 |
| Cause of error #5005? | yes | 0.668 |
| Why doesn't IntegratedML work? | yes | 0.686 |
| Monitor health states? | yes | 0.761 |
| Service/Process/Operation architecture? | yes | 0.673 |
| Does Foreign Table work? | yes | 0.677 |
| Capital of France? | no | 0.507 |
| Train a dog? | no | 0.515 |
| Chocolate cake? | no | 0.521 |

**10/10 classified correctly by the 0.58 threshold.** The relevant ones fall
between 0.667-0.761, the irrelevant ones between 0.507-0.521 — a clean gap of
~0.15, with 0.58 right in the middle. The original calibration (2 points)
confirmed with a set 5x larger; no adjustment needed to the threshold.

### 7.2 Formal comparison of chunking strategies

So as not to mix "different strategy" with "different text" (the phase docs
changed a lot since the original ingestion of 09/09/2026), the two strategies
were applied to the **same current text**, generated again in parallel tables
(`Guardian_RAG.ChunkParagraphCompare` and `Guardian_RAG.ChunkAltStrategy`) —
none of them touches the real RAG Assistant corpus in production. Alternative
strategy: a fixed window of 800 characters with 150 of overlap, **deliberately
ignoring** the paragraph boundary (it cuts in the middle of sentences) — the
"naive" hypothesis against the production strategy (groups by paragraph).

`RunChunkingComparison()` runs the 7 relevant questions, pure vector retrieval
(TOP 1), against the two tables. Real result:

| Metric | Paragraph (production) | Fixed window (naive) |
|---|---|---|
| Right-document hit (top-1) | 7/7 (100%) | 7/7 (100%) |
| Average similarity | **0.709** | 0.684 |

The paragraph strategy had **higher similarity on all 7 questions**, without
exception — the biggest difference on the IntegratedML question (0.686 vs
0.630, a gap of 0.056). Both hit the right document in 100% of cases (the
corpus is small and well separated by topic, so that metric alone does not
differentiate the strategies), but the consistently higher similarity of the
paragraph strategy is real evidence in favor of the choice already made in
Phase 3 (preserving units of meaning reduces noise in the embedding vector) —
previously justified only by reasoning, now also by quantitative comparison.

  - ["Using IRIS as a Vector Database"](https://community.intersystems.com/post/using-iris-vector-database)
    (Piyush Adhikari, 24/12/2025) — 3 fragments.
  - ["Business Rules Deep Dive: Dynamic Objects and Property Access Pitfalls - Part 1"](https://community.intersystems.com/post/business-rules-deep-dive-dynamic-objects-and-property-access-pitfalls-part-1)
    (Muhammad Waseem) — 4 fragments.
- **Real finding, not hidden**: the original attempt was to use
  `docs.intersystems.com` (official documentation), but the article body is
  rendered via JavaScript — `WebFetch` (which converts static HTML into
  markdown) only saw the navigation menu, not the article text. The Developer
  Community (`community.intersystems.com`) is server-rendered HTML and worked.
  Accuracy note: `WebFetch` processes the page with a model from the given
  prompt, so the ingested text is an extraction/condensation of the page, not a
  byte-for-byte copy of the original HTML — recorded in the `Version` of each
  `Document` ("obtained 10/09/2026") and cited in this section for anyone
  auditing the provenance.
- **Real test of value**: the question "How to deal with properties with an
  underscore in Business Rules and IRIS Dynamic Objects?" retrieved and
  correctly cited the new Developer Community article, **cross-referencing**
  the project's already-documented internal finding that the `_` operator
  breaks the ObjectScript parser (`03_PHASE_2...md`) — and **honestly abstained**
  from detailing the exact fix, because the ingested article is only Part 1 of a
  series and the fix is in Part 2 (which was not ingested) — it did not invent a
  solution it did not have.
